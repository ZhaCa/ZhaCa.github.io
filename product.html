01

从这里开始

神州数码 AgentOps 面向企业已经拥有的 Agent 和部署制品，帮助团队回答四个问题：谁在运行、完成了什么任务、结果是否正确、怎样把修复安全地带回生产。

AGENT

谁在运行

记录业务用途、负责人、来源、版本、模型与工具、执行身份及权限。外部运行与平台托管分别标注可发现、可观测和可控制范围。

TASK

做了什么

业务目标、Session、运行尝试、事件与工具证据连到同一任务。技术完成、成果审核和业务核验各自有状态。

VERSION

如何改进

基线、候选、数据集、评测、实验、审批与发布保留关联。候选修改不会直接影响正在运行的版本。

首次进入：在登录页点“一键进入演示控制台”。顶部先选工作空间和环境。当前预置管理员拥有全部演示权限；切换空间后对象和筛选按空间隔离。

建议先沿下面的主线使用：确定业务目标与验收口径 → 接入与配置 → 准备样本并做基线评测 → 建立候选并同集比较 → 双审批后发布 → 运行观测与业务核验 → 从失败证据再次改进。

02

平台能力与架构

企业组织之下按工作空间、环境管理资产和访问范围。Agent、任务、版本是贯穿各模块的三个对象；身份权限、事件处置与成本在每一步提供约束和反馈。

05 再次发布门禁审批、切换版本、业务核验

外部 Agent 纳管

通过来源连接登记资产与能力。资产发现、遥测观测、受控操作分别测试；没有控制接口时进入人工处置。同步不会凭空生成远端 Agent 或补造 Trace。

平台托管运行

管理已有部署制品的运行配置、实例、并发、配额和检查点。流量切换和恢复受版本、权限与副作用状态约束。当前运行是本地模拟。

AgentOps 负责已有 Agent 的运行管理与持续优化；完整的 Agent 构建由企业原有平台承担。问学、知识库、MaaS、Skill/MCP 与 AI for BI 可作为未来集成来源，具体接口和授权需实施时核对。

03

功能模块速查

每个入口都能从对象追到相关证据。若页面为空，先检查顶部工作空间、环境和筛选条件。

模块你在这里做什么进入后的下一步
平台总览按时间、Agent、版本筛选；运行趋势在柱状图、折线图和数据表间切换，点日期或指标下钻任务。从异常进入任务，核对技术状态和业务结果。
Agent 中心登记 Agent，查看来源、资源、运行版本、质量、事件和成本；未上线 Agent 走准入流程。到评测与优化准备数据集，再看候选版本。
Team 协作建立 Leader 与成员顺序、分派目标、退回成果并确认父任务。从子任务回到参与 Agent 的执行和结果证据。
接入与资源新建来源连接、测试与同步，登记模型、工具、Skill、知识等资源并管理风险。资源开通后绑定到候选版本与执行身份。
运行中心查看部署、实例、Session、配额、队列、检查点与流量切换。核对运行版本、任务状态和恢复前置条件。
可观测中心从指标到任务和证据；有采集才显示 Trace/Span，缺失显示“未采集”。失败证据可进入数据集，技术成功还需业务核验。
评测与优化新建数据集、导入与标注样本、选择评测器、同集回归和实验对比。通过的候选进入发布申请。
发布中心查看候选配置差异、门禁、业务放行、安全复核及发布记录。两条审批通过后手动发布，再看新任务结果。
事件中心告警诊断、计划、Dry-run、控制审批、源回执、效果核验及恢复。技术与业务都恢复后关闭并复盘。
身份与治理执行身份、资源授权、空间策略和策略模拟。权限不足时查看阻断原因，补齐授权再执行。
成本中心区分原厂账单、估算、缺失和未归属费用；设预算、分配与导出。按 Agent/空间核对费用依据，改进后看新账期。
平台设置新建空间、添加成员、调整访问、数据策略、审计与接口示例。配置完成后切换空间验证隔离范围。

新 Agent 从登记到上线

这条路径适合检查 Demo 的主要功能闭环。建议先选“智能运维”工作空间、“生产”环境，以“巡检证据助手（练习）”作为新对象。登记只建立资产，不会自动运行。

接入与资源Agent 中心评测与优化发布中心
AGENT LIFECYCLE / 操作路线按顺序点选，逐步核对01 / 07
先准备来源连接

到接入与资源点“新建来源连接”，填写平台、区域、同步间隔、资产 API、认证方式与凭据引用；观测再填遥测地址、采样和字段映射，控制再填适配地址。保存后先“测试连接”再“同步资产”。只做本地契约校验。

登记 Agent：业务 → 来源 → 资源身份 → 核对

到Agent 中心点“登记 Agent”。填名称、负责人、业务用途和验收口径；选来源连接、唯一原生 ID、外部运行或平台托管；选模型与工具并填写执行主体、凭据引用、未来到期时间；核对后提交。不要填写真实密钥。

准备能复测的样本和评分规则

点 Agent 的“开始基线验证”，或进入评测与优化选择目标 Agent，依次“新建数据集”“导入测试样本”“新建评测器”。为每个样本写输入和人工期望，选“精确匹配版本输出”或“版本输出包含预期文本”，并设阈值。

先评基线，再改候选

在数据集“标注与版本输出”保存基线实际输出，点“使用此数据集评测”。回到 Agent 点“创建优化候选”，在候选详情“修改候选配置”，填写配置摘要、变更说明及已有制品/外部运行引用。

同一快照做回归与实验

为候选补齐版本输出，并让基线、候选各运行一次同一数据集版本和评测器版本。先完成所有样本编辑，再评两版；编辑样本或配置会使旧证据失效。候选详情点“比较同集基线”，核对逐样本差异和分数。

业务放行、安全复核、手动发布

通过门禁后点“提交发布申请”。在发布中心分别处理“业务放行”和“安全复核”，两条批准后再点“发布获批版本”。管理员可演示两项职责，但每一步仍独立留证；批准不会自动切换生产版本。

发布后看任务并核验业务

回 Agent 点“调试运行”，打开新任务查看技术状态与输出，再点“业务结果核验”填写依据。技术成功只表示执行完成；业务未核验或不一致仍需处理。若结果错误，回到证据/样本进入下一轮优化。

07

事件、治理、成本与平台设置

INCIDENT

事件与受控处置

在事件中心新建事件，填 Agent、级别、负责人、诊断与计划；随后编辑计划 → Dry-run → 申请控制 → 审批 → 发送 → 记录源回执 → 核验效果 → 确认技术恢复和业务恢复 → 关闭复盘。源接受与效果生效独立显示；没有控制接口转人工工单。

IDENTITY

身份、授权与策略

在身份与治理配置 Agent 的执行主体、凭据引用、到期时间、资源范围和可选代理用户。新建空间策略选择 Agent、资源、动作、允许/拒绝与原因，再用策略模拟核对。显式拒绝会阻止本地执行。

FINOPS

预算与费用

在成本中心“设置预算”，填写金额、自然月/季度、提醒阈值和负责人。按来源区分原厂账单、估算、缺失及未归属；缺失金额不计零，估算不等于已出账。导出只包含当前空间数据。

ADMIN

空间与成员

在平台设置新建/编辑空间，添加成员姓名、邮箱、角色与当前空间访问；成员行可调整为职责访问、只读或移除并恢复。数据区域、保留、脱敏与冻结在“配置数据策略”，与预算分开。当前管理员不能移除自己的管理访问。

控制回执超时或外部写操作副作用未知时，不能自动重放。技术恢复不代表业务恢复；预算阈值是本地状态提示，不会真实通知、扣费或停机。

09

常见问题与走查清单

页面里找不到刚才的对象

先确认顶部工作空间和环境；空间切换会清除旧筛选。历史空间只读，新增操作应在普通业务空间或练习副本完成。

没有 Trace 或费用显示缺失

“未采集”是证据缺口，不是零次调用或零费用。经营分析历史只采到执行事件、工具日志和部分账单。

评测/发布按钮不能继续

检查版本输出、样本争议、同一数据集与评测器快照、候选配置、有效身份、资源授权与两项审批。编辑依据后重新评测和申请。

技术成功，为什么结果仍待核验

技术状态只说明调用完成；成果接受与业务目标正确由人工分别确认。退款等写操作还需看业务终态和副作用。
